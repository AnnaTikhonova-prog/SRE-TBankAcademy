# Метрики ShiftPlanner в VictoriaMetrics

## Стек и сбор

Приложение ShiftPlanner написано на FastAPI и работает в namespace
`shiftplanner`. Метрики приложения публикуются без авторизации внутри кластера
по `http://<pod-ip>:8000/metrics` в формате OpenMetrics. Библиотека
`prometheus-client` предоставляет стандартные метрики Python runtime; middleware
добавляет число HTTP-запросов и histogram длительности по шаблонным путям
FastAPI.

VictoriaMetrics Single развёртывается официальным Helm chart
`vm/victoria-metrics-single` в namespace `monitoring`. Параметры чарта и
конфигурация pod service discovery находятся в
`../k8s/victoria-metrics-values.yaml`. Сбор раз в 15 секунд настроен
по Kubernetes pod discovery: VictoriaMetrics оставляет только pod с аннотацией
`prometheus.io/scrape: "true"`, читает порт и путь из аннотаций.

PostgreSQL exporter `prometheuscommunity/postgres-exporter` работает sidecar-
контейнером рядом с PostgreSQL на порту `9187`. Он обращается к базе через
`localhost`, поскольку контейнеры одного pod разделяют сеть, и получает пароль
из Kubernetes Secret. Сам PostgreSQL остаётся на своём PVC.

Манифесты приложения и exporter: `../k8s/00-namespace.yaml` —
`../k8s/06-frontend.yaml`; Helm values: `../k8s/victoria-metrics-values.yaml`.
Команды установки и проверки собраны в `../k8s/METRICS.md`.

## Бизнес-метрики

| Метрика | Тип | Значение |
| --- | --- | --- |
| `shiftplanner_registered_users_total{role}` | Counter | Число регистраций аккаунтов по роли `manager` или `employee` |
| `shiftplanner_auth_logins_total{result}` | Counter | Число успешных и неуспешных попыток входа |
| `shiftplanner_companies_created_total` | Counter | Число созданных компаний |
| `shiftplanner_employees_joined_total` | Counter | Число сотрудников, вступивших в компанию по invite-коду |
| `shiftplanner_shifts_created_total` | Counter | Число успешно созданных смен |
| `shiftplanner_availability_blocks_created_total` | Counter | Число добавленных интервалов доступности сотрудников |

Метки имеют ограниченный набор значений. В них не попадают email, ID пользователей
или другие значения с высокой кардинальностью.

## Проверка

После установки и port-forward VictoriaMetrics проверьте API-запросы:

```powershell
Invoke-WebRequest 'http://localhost:8428/api/v1/query?query=up'
Invoke-WebRequest 'http://localhost:8428/api/v1/query?query=pg_up'
Invoke-WebRequest 'http://localhost:8428/api/v1/query?query=shiftplanner_shifts_created_total'
```

Запрос `up` показывает статус scrape-таргетов, `pg_up` — доступность PostgreSQL
для exporter, бизнес-счётчик — число созданных смен. Чтобы в бизнес-счётчиках
появились ненулевые значения, выполните соответствующее действие в приложении.

После развёртывания в Minikube проверено: VictoriaMetrics pod готов (`1/1`),
PVC имеет статус `Bound`; `up` возвращает 5 рядов со значением `1` (три backend
pod’а, Postgres exporter и сама VictoriaMetrics), `pg_up` равен `1`. Запрос
`shiftplanner_http_requests_total` возвращает ряды с `namespace="shiftplanner"`
и счётчиками HTTP-запросов. Запросы можно проверить через API или в UI
`http://localhost:8428/vmui/` после port-forward.
