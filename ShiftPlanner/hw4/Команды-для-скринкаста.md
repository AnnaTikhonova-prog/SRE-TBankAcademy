# Команды для записи демонстрации метрик

Перед записью откройте PowerShell в корне репозитория:

```powershell
cd C:\Users\asus\PycharmProjects\SRE-TBankAcademy
```

VictoriaMetrics, backend и Postgres exporter уже развёрнуты в Minikube. Команды ниже показывают состояние кластера и проверяют сбор метрик. Port-forward запускайте в отдельном окне PowerShell и оставляйте его работающим.

## 1. Показать запущенные компоненты

```powershell
kubectl get pods -n shiftplanner -o wide
kubectl get pods,svc,pvc -n monitoring
```

Ожидается: три backend pod’а `Running`, Postgres pod `2/2 Running`, VictoriaMetrics pod `1/1 Running` и PVC со статусом `Bound`.

## 2. Показать endpoint метрик приложения

В отдельном окне PowerShell запустите port-forward и оставьте его работающим:

```powershell
kubectl port-forward deployment/backend -n shiftplanner 8000:8000
```

В окне записи выполните:

```powershell
(Invoke-WebRequest 'http://localhost:8000/health' -UseBasicParsing).StatusCode
$metricsResponse = Invoke-WebRequest 'http://localhost:8000/metrics' -UseBasicParsing
$metricsText = [System.Text.Encoding]::UTF8.GetString($metricsResponse.Content)
$metricsText -split "`n" | Select-String '^(python_info|shiftplanner_http_requests_total|shiftplanner_.*_total)'
```

Ожидается HTTP-код `200` и строки метрик, включая `shiftplanner_http_requests_total`.

## 3. Подключиться к VictoriaMetrics

В ещё одном окне PowerShell запустите port-forward и оставьте его работающим:

```powershell
kubectl port-forward svc/vm-single-victoria-metrics-single-server -n monitoring 8428:8428
```

В окне записи запросите статус всех scrape targets:

```powershell
$targets = Invoke-RestMethod 'http://localhost:8428/api/v1/targets'
$targets.data.activeTargets | Select-Object `
  @{Name='job';Expression={$_.labels.job}}, `
  @{Name='instance';Expression={$_.labels.instance}}, health, lastError | Format-Table -AutoSize
```

Ожидается `health = up` для трёх backend pod’ов, Postgres exporter на `:9187` и VictoriaMetrics.

## 4. Показать собранные метрики

```powershell
(Invoke-RestMethod 'http://localhost:8428/api/v1/query?query=up').data.result |
  ConvertTo-Json -Depth 8
(Invoke-RestMethod 'http://localhost:8428/api/v1/query?query=pg_up').data.result |
  ConvertTo-Json -Depth 8
(Invoke-RestMethod 'http://localhost:8428/api/v1/query?query=shiftplanner_http_requests_total').data.result |
  ConvertTo-Json -Depth 8
```

Эти команды проверяют состояние scrape-целей, доступность PostgreSQL для exporter и наличие HTTP-метрик приложения. Интерфейс `http://localhost:8428/vmui/` можно показать дополнительно; для проверки сбора метрик достаточно команд выше.

Для демонстрации бизнес-счётчика выполните соответствующее действие в приложении, например создайте смену, подождите один интервал сбора и запросите:

```promql
shiftplanner_shifts_created_total
```

## 5. Остановить port-forward после записи

В каждом окне с `kubectl port-forward` нажмите `Ctrl+C`. Поместите готовый скринкаст в `ShiftPlanner/hw4` и пересоберите архив, чтобы запись вошла в него.

Примечание: в этой установке сбор метрик выполняет VictoriaMetrics Single по scrape-конфигурации Helm chart; отдельный Service `vmagent` не создавался.
