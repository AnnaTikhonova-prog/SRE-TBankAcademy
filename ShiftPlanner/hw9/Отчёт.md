# Gateway API traffic split 90/10

## Цель

В minikube развернуты две версии backend приложения ShiftPlanner. Envoy Gateway принимает HTTP-запросы и по правилам Gateway API отправляет около 90% запросов версии v1 и 10% версии v2.

## Развёртывание

Для двух версий созданы отдельные Kubernetes Deployment по две реплики и отдельные `ClusterIP` Service. Обе версии используют общую PostgreSQL, поэтому состояние приложения хранится вне pod'ов. Readiness probe `/health/db` проверяет доступность БД, liveness probe `/health` проверяет, что процесс приложения жив.

Версия ответа видна в `GET /version`, в заголовке `X-App-Version` и идентификаторе релиза `X-App-Release`. Использованы образы `shiftplanner-backend:1.0.0` (v1) и `shiftplanner-backend:2.0.0` (v2).

Манифесты находятся в каталоге `k8s/`:

- `backend-versions.yaml` — оба Deployment и ClusterIP Service `backend-v1`, `backend-v2`.
- `gateway-90-10.yaml` — Envoy GatewayClass, Gateway и HTTPRoute с весами 90 и 10.

В HTTPRoute сумма весов равна 100. Для каждого запроса Gateway выбирает целевой Service пропорционально весам backendRefs.

## Проверка распределения

26 ноября 2026 года отправлено 200 последовательных запросов `GET http://localhost:8080/version` через Envoy Gateway port-forward. Версия определялась по JSON-ответу и `X-App-Version`. Все запросы завершились HTTP 200.

| Версия | Ответов | Фактическая доля | Настроенный вес |
|---|---:|---:|---:|
| v1 (`backend-v1`) | 179 | 89,5% | 90% |
| v2 (`backend-v2`) | 21 | 10,5% | 10% |
| Всего | 200 | 100% | 100% |

Абсолютное отклонение каждой доли от заданного веса составляет 0,5 процентного пункта. На выборке из 200 запросов фактическое распределение близко к заданным 90/10. Точное количество может варьироваться между прогонами, поскольку веса задают пропорцию распределения, а не фиксированную последовательность ответов.

## Артефакты результата

Результаты конкретного прогона лежат в `artifacts/traffic-90-10-20261126-130625/`:

- `summary.csv` — количество ответов и проценты по версиям;
- `responses.csv` — запись каждого из 200 запросов с версией, release и HTTP status;
- `httproute.yaml` — применённый маршрут;
- `backends.txt` — состояние pod'ов и Service;
- `backend-v1-logs.txt`, `backend-v2-logs.txt` — журналы запросов соответствующих версий;
- `README.txt` — параметры и время проверки.

Подсчёт в `summary.csv` соответствует формуле: `доля версии = количество ответов этой версии / 200 × 100%`.

## Вывод

Две версии ShiftPlanner доступны за отдельными ClusterIP Service. Gateway API HTTPRoute настроен на веса v1/v2 90/10 и принят контроллером Envoy Gateway. Контрольная выборка из 200 HTTP-запросов дала 179 ответов v1 и 21 ответ v2 — 89,5%/10,5%, что соответствует ожидаемой близкой оценке распределения 90/10.
